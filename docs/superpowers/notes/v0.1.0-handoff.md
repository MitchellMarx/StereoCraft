## Architectural findings (2026-05-19 diagnostic session)

1. **Plan 1's mechanism (two-pass viewport + eye-region scissor + `MixinFramebuffer_Stereo` viewport-restore) splits sky and HUD correctly.** Sky renders early in `renderWorld` before anything resets the viewport; HUD is rendered by our explicit per-eye `@Redirect` after `renderWorld`. Both confirmed via Prism testing with the deployed jar.

2. **The world chunk render path bypasses Plan 1's mechanism.** Even with no shaderpack loaded, Iris is still active (its `FixedFunctionWorldRenderingPipeline.beginLevelRendering` runs and binds the main framebuffer, resetting viewport to full-screen). Embeddium/Celeritas and Distant Horizons additionally set viewport to full-screen during their chunk passes. The eye-region scissor set by the two-pass loop does not clip the chunk path on its own — verified empirically by tracing `RENDER_BACKEND.viewport` with caller stacks.

3. **Sbs2's `StereoHook.remapWorldPassViewport` is a deliberate no-op for the main-FB case** (returns `(0, 0, irisFbWidth=displayW, irisFbHeight=displayH)` — same as input). Sbs2's design is "each eye renders at native aspect into its own per-eye Iris FBO chain; final per-eye blit squishes horizontally into the eye's main-FB region." That FBO chain is implemented in `RenderTargets.java` (+525 lines in commit `fa3a63f4`) and its consumers — which Plan 2 Phase 3 Tasks 4–11 port. Plan 1's `MixinGLStateManager_StereoRemap` was an attempt to substitute for that chain at the viewport-clip layer; it doesn't generalize beyond sky+HUD.

4. **`com.gtnewhorizons.angelica.glsm.GLStateManager` is in lwjgl3ify's LaunchClassLoader transformer exclusion list.** A Mixin onto it cannot apply. (Discovered when a trace mixin produced zero output despite the class being in the deployed jar.) If a future plan needs an inline hook at the GLSM layer, target `com.gtnewhorizons.angelica.lwjgl3.Lwjgl3GLRenderBackend.viewport(IIII)V` instead — that class is NOT excluded and is the final GL11 pass-through in the LWJGL3-backend stack used by GTNH-daily. (Experimentally confirmed in commits `e94702a`→`ccece57` — the viewport-remap mixin compiled and applied, but caused severe rendering corruption because remapping viewport to half-width without compensating projection-aspect produced vertical-streak artifacts. Reverted.)

5. **Fabric port `C:\CODE\Stereoscopic` solves no-shaders world-chunk split with a scratch-FB pattern.** Each eye renders into an owned full-size scratch framebuffer via a `Minecraft.getFramebuffer()` HEAD inject, then blit-squishes scratch into the main FB's eye region. Works uniformly with and without shaders because the scratch substitution is transparent to whatever's downstream (vanilla, Iris, Embeddium/Celeritas, DH). This is **fundamentally different** from sbs2's design (which only does per-eye routing via Iris's RenderTargets — shader-on only). The scratch-FB pivot plan ports this pattern into our Forge mod.

6. **RFB transformer-handle IDs are namespaced `<pluginId>:<transformerId>`.** Angelica's GLSM redirector handle is registered as `angelica:redirector`, not the bare `"redirector"` returned by `RFBAngelicaRedirector.id()`. Discovered while fixing Plan 3's cursor-thread GLSM crash — the runtime mutation of `RfbClassTransformerHandle.exclusions()` requires matching the namespaced id. The fix: `com.gtnewhorizons.retrofuturabootstrap.Main.getRfbTransformers()` returns the handle list at the right point in FML init; FML coremod constructor is too early (handle list empty), `injectData` works, IClassTransformer constructor works. We retry at all three with an `applied = true` static guard.

## Plan architecture invariant (canonical — read this before touching plans or code)

All four plans reference a **"Porting principle"** section in Plan 1:

- **Canonical spec** = `git -C /c/CODE/Angelica-sbs2 diff master...stereo-sbs-2`. That diff IS the work — nothing outside it is in scope, nothing inside it is optional.
- **NEW files in the diff** port verbatim with package rename only.
- **MODIFIED Angelica files in the diff** apply externally via mixin / our `StereoscopicCoreMod` IFMLLoadingPlugin / our `StereoscopicRfbPlugin` (both coremod-style plugins exist; future transformer additions append to them).
- **NEVER drop sbs2 code on judgment.** Angelica is a hard runtime dependency; references like `AngelicaClassDump`, `GLStateManager`, `HUDCaching` resolve naturally.
- **NEVER invent rationale** in plan body or commit messages. State what the change does; don't fabricate "why".

### Plan-writing lesson — applies to all future plans

**Plans must not gate phase completion on Prism smoke-test rubrics whose pass conditions depend on later-plan implementation work.** Plan 1's Task 26 originally claimed "world splits L/R" as a Plan 1 exit criterion; that's a Plan 2 Phase 3 deliverable. Result: a full session burned debugging Plan 1 mixin behavior chasing an architectural gap that wasn't a Plan 1 problem.

Each plan's smoke-test rubric covers only what the plan's own implementation delivers. Implement first, test once at the end of the plan — not at the end of every task or phase. If a phase touches code whose behavior only emerges in combination with a later plan, the smoke test for that combination belongs in the later plan.
